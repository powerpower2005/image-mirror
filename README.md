# 이미지 미러링

공개 원본 이미지에서 **감시 등록 이후 새로 발견한 태그만** Docker Hub로 복사합니다. GitHub Actions가 매일 한국 시각 12:17(UTC 03:17)에 실행되며 수동 실행도 가능합니다.

첫 실행은 기준선만 저장합니다. 기존 태그를 일괄 복사하지 않습니다. 이미지 색인과 모든 플랫폼을 함께 복사하고 원본·대상의 다이제스트가 같은지 확인합니다.

## 처음 설정하기

1. Docker Hub에서 감시 대상과 같은 이름의 대상 저장소를 미리 만듭니다. 기본 대상은 `nginx`, `redis`입니다.
2. 각 대상 저장소를 공개로 설정합니다.
3. 대상 저장소의 설정에서 모든 태그를 변경 불가로 만듭니다. 전체 일치 규칙 `.*`를 사용합니다. 프로그램은 공개 메타데이터의 `immutable_tags_settings.enabled`가 참이고 규칙에 `.*` 또는 `^.*$`가 있는지 복사 직전에 확인합니다. 설정을 확인할 수 없으면 복사하지 않습니다.
4. GitHub 저장소의 **Settings → Secrets and variables → Actions**에서 아래 두 비밀값을 등록합니다.
5. **Actions → 이미지 미러링 → Run workflow**에서 기본 브랜치를 선택해 실행합니다. 첫 실행에서는 원본 태그 기준선만 생성됩니다.

| 비밀값 이름 | 용도 |
|---|---|
| `DOCKERHUB_USERNAME` | Docker Hub 로그인 계정이자 대상 이름 공간 |
| `DOCKERHUB_TOKEN` | 읽기·쓰기 권한의 액세스 토큰. 삭제 권한은 부여하지 않습니다. |

실제 계정명과 토큰을 설정 파일이나 이 문서에 쓰지 마세요. 대상 경로는 실행할 때만 조합합니다. 대상 저장소를 자동 생성하거나 변경 불가 설정을 프로그램이 대신 바꾸지 않습니다.

## 감시 대상 설정

`config/images.yaml`에 항목을 추가합니다.

```yaml
images:
  - id: nginx
    source: docker.io/library/nginx
    destination: nginx
    enabled: true
    include: ['\d+\.\d+\.\d+', '\d+\.\d+\.\d+-alpine']
    exclude: []
```

- `id`: 고유한 감시 식별자입니다.
- `source`: 공개 원본의 전체 경로입니다. 태그, 다이제스트, 인증정보는 넣지 않습니다.
- `destination`: 대상 저장소 이름만 적습니다. 계정명은 넣지 않습니다.
- `enabled`: `false`이면 조회와 복사를 중지합니다.
- `include`: 태그 전체가 정규식에 일치해야 합니다. 빈 목록이면 모두 허용합니다.
- `exclude`: 일치하는 태그를 제외하며 포함 조건보다 우선합니다.

기본 필터는 `1.29.3`, `1.29.3-alpine` 같은 완전한 버전 태그만 허용합니다. `latest`, `1.29`, `alpine`은 제외합니다. 완전한 버전 태그도 원본에서 변경될 수 있으므로 복사할 때는 조회한 다이제스트로 고정합니다.

새 항목은 다음 조회에 성공했을 때 전체 태그를 기준선으로 저장하며 복사하지 않습니다. **등록 시점은 설정 수정 시각이 아니라 최초 태그 조회 성공 시각입니다.** 필터 적용 전 전체 태그를 저장하므로 나중에 필터를 넓혀도 등록 전에 있던 태그는 복사하지 않습니다. 등록 이후 생겼지만 이전 필터에 제외됐던 태그는 새 필터에서 후보가 될 수 있습니다.

새 대상을 추가할 때는 해당 Docker Hub 저장소의 공개·태그 변경 불가 설정도 준비해야 합니다. 같은 식별자의 원본 또는 대상을 바꾸면 실행을 중단합니다. 바꿀 때는 새 식별자로 등록합니다. 식별자와 대상 저장소는 중복될 수 없습니다.

중지한 항목의 기록은 유지합니다. 다시 활성화하면 중지 기간에 생긴 태그도 후보가 됩니다. 설정에서 지워도 과거 기록은 자동 삭제하지 않습니다. Docker Hub 계정을 바꿀 때는 기존 완료 기록이 새 계정을 나타내지 않으므로 새 식별자로 등록하거나 기록 이전을 별도로 검토해야 합니다.

## 복사와 덮어쓰기 방지

복사 후보는 현재 태그 중 필터를 통과하고 최초 기준선·미러링 완료·충돌 기록 어디에도 없는 태그입니다.

| 대상 상태 | 처리 |
|---|---|
| 명확히 태그가 없음 | 원본 다이제스트로 고정해 복사한 뒤 검증 |
| 원본과 같은 다이제스트 | 복사 없이 검증 완료로 기록 |
| 원본과 다른 다이제스트 | 덮어쓰지 않고 충돌 기록과 경고 |
| 인증·권한·호출 제한·통신 오류 | 복사하지 않고 실패 처리 |

```bash
crane copy --no-clobber 원본@sha256:다이제스트 대상:태그
```

`--platform`을 사용하지 않아 전체 이미지 색인을 복사합니다. `docker pull/tag/push`는 사용하지 않습니다. `--no-clobber`의 확인과 업로드 사이에 다른 프로그램이 접근할 수도 있으므로 절대적인 덮어쓰기 방지는 Docker Hub의 변경 불가 설정이 담당합니다.

표시하는 플랫폼 목록에서만 증명 자료용 `unknown/unknown`을 제외합니다. 원본과 대상에 복사되는 데이터에서는 제외하지 않습니다. 단일 플랫폼 이미지는 이미지 설정의 운영체제·아키텍처·변형 정보를 사용합니다.

색인에 포함된 증명 자료는 함께 복사합니다. 별도 참조나 별도 태그로 보관된 서명·소프트웨어 구성 명세서까지 옮기지는 않습니다. **검증됨은 처리 당시 원본·대상 다이제스트가 같다는 뜻입니다.** 서명 검증이나 취약점 검사를 의미하지 않습니다.

미러링한 태그는 원본이 바뀌어도 갱신하지 않습니다. 매번 최신 내용을 동기화하는 도구가 아닙니다.

## 기록과 재시도

`state/images.json`에는 원본, 대상 저장소 이름, 최초 기준선, 확인 시각, 검증 완료 및 충돌 기록을 저장합니다. 계정명과 인증정보는 저장하지 않습니다. 시각은 UTC입니다.

- 기준선은 최초 한 번 저장하며 이후 확장하지 않습니다.
- 마지막 확인 시각은 원본 태그 목록 조회에 성공했을 때만 갱신합니다.
- 복사·검증·통신 오류는 완료 또는 충돌 기록으로 남기지 않아 다음 실행에서 재시도합니다.
- 대상에 다른 내용이 있는 충돌은 `skipped_tags`에 기록하며 자동 재시도하지 않습니다. 복구가 필요하면 원인과 대상 정책을 검토한 후 기록을 수동 조정합니다.
- 복사 성공 후 기록 전에 중단되면 다음 실행에서 같은 다이제스트를 확인해 기록을 복구합니다.
- 기준선 생성과 태그 처리마다 임시 파일에 기록한 뒤 교체합니다. 파일 누락이나 손상을 빈 기록으로 간주하지 않습니다.
- 일부 대상이 실패해도 다른 대상은 계속 처리합니다. 처리 오류가 있으면 진행 내용을 저장한 뒤 실패로 종료합니다. 충돌 건너뜀은 경고입니다.

실행이 취소되지 않았다면 상태 파일과 이 문서의 변경을 봇이 기본 브랜치에 커밋합니다. 일반 오류가 있어도 완료된 진행 내용은 저장합니다. 업로드 충돌이 나면 재배치하고 해결되지 않으면 실패하며 강제 업로드하지 않습니다. 분기 보호 규칙이 봇의 직접 업로드를 막으면 기록 저장도 실패하므로 저장소 정책을 맞춰 주세요.

## 개인정보 보호

로그·경고·오류·자동 생성 표·작업 이름·커밋 메시지는 한국어로 작성합니다. 대상은 `nginx:1.29.3`처럼 계정명 없이 표시합니다. 외부 명령 출력, 명령 인자, HTTP 응답, 원시 예외는 그대로 출력하지 않습니다. GitHub의 비밀값 자동 가리기와 프로그램의 출력 제한을 함께 적용합니다.

인증은 `--password-stdin`을 사용하며 추적 출력인 `set -x`는 사용하지 않습니다. 인증 파일은 실행기 임시 폴더에 저장하고 종료 시 삭제합니다. Actions는 커밋 해시로, 도구와 파이썬 의존성은 버전으로 고정합니다. crane 다운로드 파일은 고정한 SHA-256으로 검증합니다.

Actions 커밋은 `github-actions[bot]`과 GitHub 봇의 비공개용 이메일을 사용합니다. 로컬에서 커밋할 때도 이 저장소에만 본인의 GitHub 비공개용 이메일을 설정하고, GitHub 계정의 이메일 비공개 및 개인 이메일 노출 업로드 차단을 켜세요. 업로드 전에 작성자와 커미터를 함께 확인합니다.

```bash
git log --format='%an <%ae> | %cn <%ce>'
```

`.docker/`, `.env`, `*.env`, `__pycache__/`, `.venv/`, `.DS_Store`는 버전 관리에서 제외합니다. Docker Hub의 공개 이미지 경로 자체에는 계정명이 있으므로 계정 자체의 익명성은 보장하지 않습니다.

## 실행과 검증

파이썬 3.12와 crane 0.22.1을 사용합니다. 인증정보를 저장소에 넣지 않고 환경 변수로 전달합니다.

```bash
python -m pip install 'PyYAML==6.0.3'
python -m unittest discover -s tests -v
# Docker Hub 인증 후 DOCKERHUB_NAMESPACE 환경 변수를 설정한 상태에서 실행합니다.
python scripts/mirror.py
```

자동 테스트는 원본·대상 응답을 모의하므로 Docker Hub로 이미지를 올리지 않습니다. 기본 브랜치 업로드와 변경 제안에서도 별도의 읽기 전용 자동 검증을 실행합니다.

실제 복사 검증은 별도 테스트 저장소와 별도 기록 파일로 진행하세요. 기준선을 만든 후 테스트용 기록에서 태그 하나만 제외하고 실행해 해당 태그만 복사되는지 확인합니다. 원본·대상 다이제스트, 플랫폼, 색인 내 증명 자료가 같은지 확인하고 서로 다른 내용으로 같은 태그를 올릴 때 거절되는지도 확인합니다. 운영 기준선은 테스트 목적으로 수정하지 마세요.

## 알려진 제약

- 예약 실행은 지연되거나 누락될 수 있습니다. 두 실행 사이에 생겼다가 삭제된 태그는 발견할 수 없습니다.
- 공개 저장소에서 60일간 활동이 없으면 예약 실행이 중지될 수 있습니다. 정상 조회 때 확인 시각을 갱신하므로 보통 매일 봇 커밋이 생깁니다. 중지되면 Actions에서 다시 활성화하세요.
- `crane digest`는 HEAD 요청을 우선하지만 실패하면 GET 요청으로 재시도할 수 있습니다. 로그인해도 Docker Hub 무료 계정의 호출 제한이 없어지지는 않습니다.
- 공개 원본만 대상으로 합니다. 다른 공개 레지스트리도 표준 API를 지원하면 사용할 수 있지만, 추가 인증이나 특수 배포 제약은 별도 대응이 필요합니다.
- 작업 중 취소나 실행기 종료가 발생하면 아직 원격에 커밋하지 못한 기준선이 사라질 수 있습니다. 저장된 원격 기준선이 없는 항목은 다음 실행에서 다시 기준선을 잡습니다.
